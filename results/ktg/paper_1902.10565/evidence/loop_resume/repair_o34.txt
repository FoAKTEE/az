What changed, in one line each:
  o34  synchronous_loop_9x9.sh:2 and export_model_for_selfplay_9x9.sh:2 now read
       `set -eu -o pipefail`. A shebang's options are dropped when a script is
       handed to an interpreter (`bash "$LOOP_SH"`, loop.sbatch), so -e and -u
       were off for the whole archive-staging section; they are now in the body
       and hold however the file is invoked. The staging section was audited
       command by command against errexit (PART 1b) and nothing there needed a
       guard: the only kinds of command that may legitimately return non-zero
       are if/case/for conditions, the `rm -rf .../*.exported` and `*.tmp`
       sweeps, and the scratch-guard call already bracketed by set +e / set -e.
  o33a a SIGTERM seen during the pre-flight now stops the wrapper BEFORE the
       loop is launched (loop.sbatch, just above the launch).
  o33b the loop's own exit status is recorded the instant it is known, and a
       non-zero status already in hand outranks a SIGTERM that arrives after it.
  o33c the loop bumps $BASEDIR/.cycles_completed after every cycle whose five
       stages returned 0; the wrapper reads it at entry and in finalize, and a
       link that advanced it restarts the run of consecutive failures. Without
       this the breaker counted three failures EVER, because a healthy
       production link never exits 0.
  o33d documented, not changed: KTG_MIN_RUNTIME_SECONDS / KTG_MAX_FAILS /
       KTG_MAX_CHAIN ride down the whole chain on Slurm's default --export=ALL.
       They stay operator knobs; KTG_RC_SIGTERM and KTG_RC_SCRATCH_STOP stay
       hard-coded constants.
